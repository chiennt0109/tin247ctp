🤝 Meet-in-the-Middle và tìm kiếm hai phía

Meet-in-the-Middle chia không gian trạng thái thành hai nửa, sinh kết quả từng nửa rồi ghép bằng sort, binary search hoặc two pointers. Tìm kiếm hai phía cũng mở rộng đồng thời từ điểm đầu và điểm đích để giảm độ sâu hiệu dụng.

🎯 Mục tiêu bài học

Cần hiểu

  • Vì sao chia n thành n/2 làm giảm không gian hàm mũ.
  • Cách sinh hai tập trạng thái.
  • Ghép bằng sort + lower_bound/upper_bound.
  • Ghép bằng two pointers.
  • Nguyên lý Bidirectional BFS.

Cần làm được

  • Giải Subset Sum n≈40.
  • Tìm tổng lớn nhất không vượt S.
  • Đếm số tập con có tổng bằng S.
  • Giải Four Sum bằng tổng cặp.
  • Viết Bidirectional BFS trên đồ thị không trọng số.

1. Đặt vấn đề

Bài toán mở đầu – Subset Sum.
Cho n≤40 số nguyên dương và S. Hãy tìm tổng lớn nhất không vượt S có thể tạo bởi một tập con.

Duyệt 2⁴⁰ trạng thái là quá lớn. Nhưng nếu chia thành hai nửa khoảng 20 phần tử:

  • Mỗi nửa chỉ có khoảng 2²⁰ ≈ 1 triệu tổng.
  • Sinh danh sách tổng trái và tổng phải.
  • Với mỗi tổng trái x, tìm tổng phải lớn nhất ≤ S−x.
O(2ⁿ⧸² · log 2ⁿ⧸²) thay cho O(2ⁿ)
Tư duy chung: khi toàn bộ không gian quá lớn nhưng trạng thái có thể tách thành hai phần gần độc lập, hãy sinh và ghép hai nửa.

2. Meet-in-the-Middle

1. Chia

Chia dữ liệu thành nửa trái L và nửa phải R.

2. Sinh

Sinh mọi trạng thái hoặc tổng có thể của từng nửa.

3. Ghép

Sort một phía rồi dùng binary search/two pointers.

MITM không phải chia để trị thông thường. Ta thường sinh toàn bộ trạng thái mỗi nửa rồi phối hợp, thay vì đệ quy giải hai bài toán độc lập và ghép kết quả duy nhất.

5. Four Sum bằng tổng cặp

Cho bốn nhóm A, B, C, D, cần đếm số bộ có a+b+c+d=0. Sinh:

AB = mọi a+b; CD = mọi c+d; đếm số cặp AB + CD = 0

Binary search

Sort CD. Với mỗi x trong AB, đếm số lần −x xuất hiện trong CD.

Two pointers

Sort AB tăng và CD tăng; đặt i đầu AB, j cuối CD rồi dịch theo tổng.

6. Bidirectional BFS

BFS một phía tới khoảng cách d mở rộng xấp xỉ bᵈ node. Tìm từ hai phía chỉ cần đi khoảng d/2 từ mỗi phía, gần bᵈ⧸² mỗi phía.

Điều kiện phù hợp

  • Đồ thị không trọng số hoặc mọi cạnh cùng chi phí.
  • Biết rõ start và target.
  • Có thể sinh cạnh ngược hoặc đồ thị vô hướng.

Nguyên tắc

  • Duy trì hai frontier.
  • Thường mở rộng frontier nhỏ hơn.
  • Dừng khi hai vùng đã thăm gặp nhau.
Không cộng đơn giản hai khoảng cách nếu cách đánh dấu/gặp nhau sai. Cần xác định node hoặc cạnh giao nhau và dùng distStart + distTarget.

9. Code mẫu

vector<long long> generateSums(
    const vector<long long>& values
) {
    int n = values.size();
    vector<long long> sums;
    sums.reserve(1ULL << n);

    for (int mask = 0; mask < (1 << n); mask++) {
        long long sum = 0;

        for (int bit = 0; bit < n; bit++) {
            if (mask & (1 << bit)) {
                sum += values[bit];
            }
        }

        sums.push_back(sum);
    }

    return sums;
}

long long bestSubsetSum(
    const vector<long long>& a,
    long long limit
) {
    int middle = a.size() / 2;

    vector<long long> left(
        a.begin(),
        a.begin() + middle
    );

    vector<long long> right(
        a.begin() + middle,
        a.end()
    );

    vector<long long> leftSums
        = generateSums(left);

    vector<long long> rightSums
        = generateSums(right);

    sort(rightSums.begin(), rightSums.end());

    long long answer = LLONG_MIN;

    for (long long x : leftSums) {
        auto iterator = upper_bound(
            rightSums.begin(),
            rightSums.end(),
            limit - x
        );

        if (iterator == rightSums.begin()) {
            continue;
        }

        --iterator;
        answer = max(answer, x + *iterator);
    }

    return answer;
}
long long countSubsetsWithSum(
    vector<long long> leftSums,
    vector<long long> rightSums,
    long long target
) {
    sort(rightSums.begin(), rightSums.end());

    long long answer = 0;

    for (long long x : leftSums) {
        auto range = equal_range(
            rightSums.begin(),
            rightSums.end(),
            target - x
        );

        answer += range.second - range.first;
    }

    return answer;
}

int bidirectionalBfs(
    int start,
    int target
) {
    if (start == target) return 0;

    queue<int> fromStart;
    queue<int> fromTarget;

    vector<int> distStart(n, -1);
    vector<int> distTarget(n, -1);

    fromStart.push(start);
    fromTarget.push(target);

    distStart[start] = 0;
    distTarget[target] = 0;

    while (!fromStart.empty()
           && !fromTarget.empty()) {
        if (fromStart.size()
            <= fromTarget.size()) {
            int layerSize = fromStart.size();

            while (layerSize--) {
                int u = fromStart.front();
                fromStart.pop();

                for (int v : adj[u]) {
                    if (distStart[v] == -1) {
                        distStart[v] = distStart[u] + 1;
                        fromStart.push(v);
                    }

                    if (distTarget[v] != -1) {
                        return distStart[v]
                             + distTarget[v];
                    }
                }
            }
        } else {
            // Mở rộng một lớp từ target tương tự.
        }
    }

    return -1;
}

10. Giải thích code

10.1. Vì sao chỉ sort rightSums?

Chỉ cần một phía được sort để binary search cho từng tổng phía còn lại. Sort cả hai chỉ cần khi dùng two pointers.

10.2. Vì sao dùng upper_bound(limit-x) rồi lùi một bước?

upper_bound trả về phần tử đầu tiên lớn hơn giới hạn. Phần tử ngay trước đó là giá trị lớn nhất không vượt giới hạn.

10.3. Vì sao cần equal_range khi đếm?

Cùng một tổng có thể xuất hiện nhiều lần từ các tập con khác nhau. equal_range cho cả đoạn có giá trị cần tìm.

10.4. Vì sao Bi-BFS mở rộng frontier nhỏ hơn?

Giảm số node sinh ra trong bước tiếp theo và cân bằng hai phía.

11. Lỗi thường gặp

  • Vẫn sinh 2ⁿ trạng thái thay vì hai nửa.
  • Quên sort trước binary search.
  • Dùng lower_bound thay upper_bound khi cần giá trị lớn nhất ≤ giới hạn.
  • Không tính multiplicity khi đếm tổng.
  • Dùng int cho tổng lớn.
  • Bi-BFS trên đồ thị có trọng số không đều.
  • Không có cạnh ngược khi tìm từ target trên đồ thị có hướng.
  • Dừng khi frontier “gần nhau” nhưng chưa thật sự giao.
